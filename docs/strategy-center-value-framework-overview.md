### 2.2 价值的定义边界

| 策略中心可以认领 | 策略中心不能认领 |
|---|---|
| 生产事实：任务数、覆盖、上线时效【F】 | 推荐算法的排序提升（算法桶 vs 随机桶） |
| 框架任务的承接转化【F】，**明确标注不是增量** | 自然转化、新商户/新场景展业贡献（当前无法可靠拆解） |
| 选人阈值处的增量（找人价值）【E1】 | 权重标签带来的曝光优势 |
| 随机桶内的组合优势（组合价值）【E1】 | 人工独有活动（H3）的效果 |
| 人力和周期节省【F/E2】 | 共同覆盖人群的结果（只能记为“共同”） |
| 预测准确性【F】 | “占业务目标的百分比”（分母无法拆解） |

## 3. 七个分析模块

每个模块写明：要回答的问题 → 方法 → 核心指标 → 证据等级 → 所需数据 → 当前状态。

### 模块 A　覆盖分区与承接（事实底座）

- **问题**：框架任务覆盖了谁、曝光了谁、承接了多少转化；和人工重叠了多少。
- **方法**：按月初人群包成员关系，把可投放用户全集 U 分成四个区（用户层互斥）：
  - Z1 仅框架覆盖（再拆成 Z1a 真新覆盖 / Z1b 替代覆盖）
  - Z2 仅人工覆盖
  - Z3 共同覆盖
  - Z4 均未覆盖

  任务层承接允许重叠，但必须同时报去重值。
- **核心指标**：各区人数、曝光率、承接转化人数（首次曝光后 N 日内）、Z3 重叠人数与去重合计、曝光份额、胜出率（同权重档位内）。
- **等级**：【F】。
- **数据**：人群包、曝光日志（task_id）、候选日志、转化表——**已具备**（K2）。
- **待补充**：U 的定义【待补充：行业线可投放用户口径】；P5、P6、P8。
- **状态**：✅ 可以做。

### 模块 B　找人增量：选人阈值断点比较（RDD）

- **问题**：框架“选中”一个用户，比“差一点没选中”多带来多少转化？
- **方法**：对每月的框架候选用户，以选人分数为运行变量，比较阈值两侧用户当月的结果。
  - 处理变量 = 是否入选任何框架人群。
  - 结果 = 用户层当月目标行为（**不论有没有曝光**，即意向处理效应 ITT，自然包含推荐算法没曝光的情况）。
  - 局部线性回归，报告 2–3 个带宽下的结果。
- **反事实含义**：阈值下方的用户**照常可能被人工任务覆盖**，所以估出来的是“在现有人工投放之上，框架再选中这个人的增量”。这正是策略中心应该认领的部分。
- **核心指标**：阈值处局部增量（pp）及 95% CI；按分数段的增量梯度（如果每月阈值不同，可以拼出“增量-分数曲线”）；外推到 Z1 的保守值和中性值。
- **等级**：阈值处【E1】；外推到全部入选用户【E1，带外推假设】。
- **数据**：候选人、分数、入选标记——**已具备**（K1）。
- **待补充**：P3（阈值规则）、P4（人工改名单）。
- **状态**：✅ 可以做，P3 和 P4 确认后定稿。

### 模块 C　组合增量：随机桶内比较

- **问题**：给**同一类用户**看框架任务还是人工任务，哪个转化更好？（衡量货品和渠道组合的质量）
- **方法**：在 5% 随机桶内，取 Z3 共同覆盖用户（候选里同时有 F 任务和人工任务），以“**当月第一次定向曝光是 F 任务还是人工任务**”作为随机分组，比较用户 N 日结果。
  - 以用户为单位，不以曝光为单位，避免多次曝光和用户内相关。
  - 分别和 H1（经验任务）、H2（BI 半自动任务）比较；随机桶内权重不生效，所以 **H2 也可以直接比较**。
- **核心指标**：用户 N 日转化率差及 95% CI；按货品类型、渠道拆分。
- **等级**：【E1】（前提是 P2 等概率随机成立，或者能按概率加权）。
- **数据**：分桶标识、曝光日志、候选日志——**已具备**（K3）。
- **限制**：只能说明“随机分发下”的组合质量；在算法桶里两类任务被算法利用的程度可能不同，这部分属于分发层，不计入。
- **注（取决于 P1）**：如果随机桶**不遵守人群定向**，那么在随机桶内，“F 任务曝光给入选用户”和“F 任务曝光给未入选用户”也是随机的。这样可以直接测出**人群识别的价值**（同一任务，给对的人 vs 给随机的人），这会是比 RDD 更直接的证据。
- **状态**：✅ 可以做，P1 和 P2 确认后定稿。

### 模块 D　分发层隔离（推荐算法与权重）

- **问题**：哪些效果属于推荐算法和权重标签，必须从策略中心的账上排除？
- **方法**：用随机桶与算法桶的对比（两个桶都是 user_id hash 分流）：
  - 推荐算法整体提升 = 算法桶 − 随机桶 → **归推荐团队**；
  - 权重 + 算法对任务曝光份额的影响 = 某类任务（如 H2）在算法桶的曝光份额 − 在随机桶的曝光份额 → **归分发层**；
  - F 任务在两个桶的曝光份额差 → 说明算法对框架任务是“偏爱”还是“压制”，作为诊断信息，**不计入任何一方的价值**。
- **等级**：【E1】（hash 分流，但需要做 A/A 平衡检验，见 §5.4）。
- **状态**：✅ 可以做。

### 模块 E　效率

- **问题**：同样的工作，人力和时间省了多少？覆盖和供给盘活扩大了多少？
- **核心指标**：自动化任务占比【F】、目标到上线周期【F；人工侧部分为 E2】、运营和 BI 人日【F 或 E2，取决于 P9】、定向覆盖去重人数【F】、供给盘活率【F；有统一货品池时可算，否则 N/A：待补充】、生产稳定性【F】。
- **货币化**：只有人日可以按人力成本折算为成本节约，并注明“只有释放出来的人力被重新配置时才是真实节约”。
- **状态**：✅ 可以做，人日的精度取决于 P9。

### 模块 F　预测确定性

- **问题**：策略中心能否在月初说清楚“框架这个月大概能承接多少、有多少增量”，月末能否兑现？
- **方法**：
  - 承接预测 = Σ 子人群（入选人数 × 可投放率 × 曝光率 × 转化率），用近 3 个月数据加收缩估计，输出 P10/P50/P90。
  - 增量预测 = 入选人数 × 模块 B 的历史增量区间（**模块 B 连续 ≥ 3 个月稳定以后才启用**）。
  - 月末按“规模 → 可投放 → 曝光 → 转化”做偏差拆解，曝光率偏差归分发层。
- **核心指标**：WAPE、偏差方向、区间覆盖率（目标接近 80%）、承诺完成率（承诺值用 P25）、连续达成月数。
- **状态**：✅ 可以做，需要 ≥ 3 个月才有评价意义。

### 模块 G　质量围栏

- **问题**：覆盖和效率的提升，有没有以补贴浪费、用户打扰、挤压人工活动为代价？
- **核心指标**：补贴 ÷ 承接、人均定向曝光频次、投诉和退订率、承接用户次月留存、货品集中度、H3 曝光达成率、风控指标【待补充：各行业线的现有风控口径】。
- **作用**：**只用来否决**价值主张，不用来证明价值。
- **状态**：✅ 可以做。

## 5. 框架有效性评估

这一节回答：**这套框架得出的结论有多可信、在什么情况下会出错、怎么提前发现它出错了。**

### 5.1 评估维度

| 维度 | 要回答的问题 |
|---|---|
| 构念效度 | 指标测的是不是我们想测的东西？（例如承接 ≠ 贡献） |
| 内部效度 | 因果结论能不能排除其他解释？ |
| 外部效度 | 局部结论能不能推广到全体用户、其他月份、其他行业线？ |
| 统计功效 | 样本量够不够发现有意义的差异？ |
| 稳健性 | 换口径、换带宽、换窗口，结论还在吗？ |
| 抗操纵性 | 团队会不会为了指标好看而改变行为，使指标失真？ |
| 可操作性 | 数据和人力成本能否支撑每月稳定产出？ |

### 5.2 逐模块评估

| 模块 | 构念效度 | 内部效度 | 外部效度 | 统计功效 | 可操作性 | 主要风险 | 综合判断 |
|---|---|---|---|---|---|---|---|
| A 承接 | **中**：衡量“参与”，不衡量“贡献” | 不做因果 | 高 | 高 | 高 | 被当成贡献引用 | 作为事实底座有效；**单独使用会误导** |
| B 找人增量 | **高** | **高**（前提见 A1–A3） | **低–中**：只代表阈值附近的“边际用户” | 中（取决于阈值附近样本量） | 中 | 人工改名单；阈值处有其他干预同时跳变；外推过度 | **主力增量证据**；外推结论必须带假设说明 |
| C 组合增量 | **高** | **高**（前提见 A4–A5） | **中**：随机分发 ≠ 算法分发；Z3 用户 ≠ 全体 | **中**：5% 桶，单月可能不够，需要多月合并 | 高 | 随机不等概率；样本不足导致“不显著”被误读为“没差别” | **主力组合证据** |
| D 分发隔离 | 高 | 高 | — | 高 | 高（推荐团队配合） | 两桶用户本身不平衡 | 有效 |
| E 效率 | **中**：人日减少不一定代表价值（可能只是转移到其他工作） | **低**：前后对比混杂其他变化 | 高 | — | 中 | 问卷估算偏差；人力未真正释放 | 有效，但必须注明口径 |
| F 预测 | **高**（直接衡量确定性） | 不做因果 | 中（季节性、新行业线） | 需 ≥ 3–6 个月 | 高 | 前几个月区间过宽或过窄 | 有效，但起效慢 |
| G 围栏 | 中 | 低 | 高 | 中 | 高 | 阈值设定主观 | 作为否决机制有效 |

**整体结论**：

1. **框架对“找人价值”和“组合价值”能给出准实验级证据（E1）**，这是不加实验分流时能达到的最高等级。K1 和 K3 让框架从“观测估算为主”升级到了“准实验为主”。
2. **框架不能给出“策略中心整体贡献 = X”这样的单一数字。** 找人增量（局部）、组合增量（随机分发下）、分发层效果三者无法在不加实验的情况下合成为一个可信的总数。这是框架有意保留的限制，不是缺陷。
3. **最大的有效性风险是外推。** RDD 只代表边际用户，随机桶只代表随机分发条件。所有外推结论都要标出假设，并且给出保守值。

### 5.3 关键假设清单

| # | 假设 | 用在哪里 | 怎么检验 | 不成立时怎么办 |
|---|---|---|---|---|
| A1 | 阈值附近的用户**无法被操纵**（分数月初算好，没有人为调整） | 模块 B | 检查阈值两侧的用户密度是否连续（McCrary 检验）；统计人工改名单的比例（P4） | 剔除被调整的用户；比例过高时降级为 E2 |
| A2 | 阈值处**没有其他干预同时跳变**（例如 BI 也用同一个分数选人、其他系统按同一阈值做事） | 模块 B | 检查阈值两侧的人工覆盖率、其他任务曝光、上月行为是否连续 | 改用“模糊断点”，或者把同时跳变的干预纳入处理变量 |
| A3 | 选中一个用户**不会影响其他用户**（例如券预算有限，选中 A 就挤掉 B） | 模块 B | 检查预算是否触顶；比较预算宽松月和紧张月的结果 | 预算触顶的月份标注“可能高估” |
| A4 | 随机桶内任务分发**真正随机**（等概率，或者概率已知） | 模块 C | 比较 F 组和 H 组用户的分发前特征（上月活跃、交易）是否平衡；比较实际曝光份额与理论份额 | 按曝光概率加权；不平衡时降级 |
| A5 | user_id hash 分流**与用户行为无关** | 模块 C、D | A/A 检验：比较两个桶在分发前月份的指标 | 用分发前的差异做 DiD 校正 |
| A6 | 转化窗口**足够长** | 全部 | 7 / 14 / 30 日窗口做敏感性分析 | 选结论稳定的窗口 |
| A7 | 结果指标**与业务目标方向一致** | 全部 | 与行业线负责人确认（P5） | 调整指标 |
| A8 | 历史 3 个月的转化率对下月**有代表性** | 模块 F | 回测：用前几个月的数据预测已知月份 | 加入季节性因子；放宽区间 |

### 5.4 框架自检机制（每月自动运行）

| 自检 | 做法 | 通过标准 | 不通过时 |
|---|---|---|---|
| 安慰剂月份 | 把 RDD 套用到框架上线前的月份 | 估计值的 CI 包含 0 | 当月模块 B 降级为 E2 |
| 安慰剂阈值 | 在真实阈值两侧各取若干个假阈值 | 假阈值处没有显著跳变 | 检查 A2 |
| 密度检验 | 阈值两侧的用户密度 | 无显著跳变 | 检查 A1 |
| 协变量平衡 | 阈值两侧、随机桶内两组的分发前特征 | 标准化差异 < 0.1 | 降级或校正 |
| A/A 检验 | 随机桶 vs 算法桶在分发前月份的指标 | 无显著差异 | 模块 D 做 DiD 校正 |
| 方法三角互证 | 比较 RDD（E1）和匹配 DiD（E2）在 Z1 的估计 | E2 ≥ E1，且方向一致（E2 预期会偏高） | 如果 E2 < E1 或方向相反，说明某个方法有问题，需要排查 |
| 窗口敏感性 | 7 / 14 / 30 日窗口 | 结论方向不变 | 报告最保守的窗口 |
| 预测回测 | 滚动用历史数据预测已知月份 | 区间覆盖率在 70%–90% | 调整区间宽度 |

### 5.5 统计功效预估（以下数字均为【虚构】，待用 P11 的真实量级替换）

**公式**：两组比例比较，最小可检测差异 MDE ≈ (z₁₋α/₂ + z₁₋β) × √(2p(1−p)/n)。取 α = 0.05、功效 80% 时，系数约为 2.8。RDD 的有效样本量约为同等随机实验的 1/3，即 MDE 约放大 √3 ≈ 1.7 倍。

| 场景 | 假设【虚构】 | 单月 MDE | 合并 3 个月 MDE |
|---|---|---|---|
| 模块 C（随机桶内 F vs H1） | Z3 共 180 万人 × 5% = 9 万；有定向曝光的 70%；F 组和 H1 组各约 3 万；基础转化率 15% | ≈ 0.8pp | ≈ 0.5pp |
| 模块 B（RDD） | 阈值两侧带宽内各 20 万人；基础转化率 17% | ≈ 0.3pp × 1.7 ≈ 0.6pp | ≈ 0.3pp |

**解读**：

- 如果业务上有意义的组合差异只有 0.3–0.5pp，模块 C **单月很可能“不显著”**。月报中要写“未观察到显著差异（单月可检测下限约 0.8pp）”，而不是“没有差异”。
- 需要用 P11 的真实量级重新计算。【待补充】

### 5.6 抗操纵性（指标会不会被“刷”）

| 可能的行为 | 会让哪个指标虚高 | 框架中的防线 |
|---|---|---|
| 框架专挑“本来就会转化”的用户 | 承接、识别精度 | 承接不作为 KPI；RDD 衡量的是增量，挑高自然转化的人不会抬高 RDD；分数段增量梯度会暴露这种情况 |
| 扩大人群包以增加覆盖 | 覆盖人数 | 围栏（打扰、补贴效率）；RDD 会显示边际增量下降 |
| 多生产低质量任务 | 任务数、自动化占比 | 任务采纳率、人工修改率；承接 ÷ 任务数 |
| 压低预测以保证“达成” | 承诺完成率 | 偏差方向指标（长期偏向同一方向就告警）；区间覆盖率过高也告警 |
| 把人工独有活动也改为框架任务 | 自动化占比 | H3 单独统计；H3 曝光达成率作为围栏 |

**建议的 KPI 组合**（而不是单一指标）：RDD 增量下界 + 预测区间覆盖率 + 人日节省 + 围栏无告警。

### 5.7 已知盲区（框架明确不回答的问题）

1. 策略中心占业务目标的比例——分母中的展业贡献和自然转化当前无法可靠拆解。
2. 框架策略的“总增量”单一数字——各模块的证据条件不同，不能直接相加。
3. 高分用户（远离阈值）的增量——RDD 只能直接回答阈值附近；高分用户的增量只能外推。
4. 框架任务在算法桶中的组合效果——与推荐算法交互，当前无法可靠拆解。
5. 长期效应（例如对用户习惯和次年留存的影响）——当前只看月内和次月。

### 5.8 降级规则（结论什么时候必须降级）

| 情况 | 处理 |
|---|---|
| 任一 E1 前提的自检不通过 | 当月该结论降为 E2，只在内部版出现 |
| CI 跨 0 | 只说“未观察到显著差异”，并写出可检测下限 |
| 连续两个月方向相反 | 暂停对外引用，排查原因 |
| 关键字段缺失率 > 【待补充：建议 5%】 | 相关指标标 N/A |
