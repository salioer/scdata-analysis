## 3. 管理层主指标：策略中心带来的业务增量

### 3.1 定义

> **业务增量** = 在其他一切照常的前提下（人工照常投放、推荐算法照常分发、供给不变），**框架策略选中这批用户**所带来的额外目标行为。

- 包含：框架选人、货品和渠道组合、周期内的调优和下线决策带来的综合效果。
- 不包含：推荐算法本身的价值、自然转化、新供给。
- 注意：被框架选中的用户里，有一部分也被人工覆盖了（Z3）。阈值下方的对照用户同样可能被人工覆盖，所以估出来的是**在人工已有投放之上**再多出来的部分，不会和人工重复认领。
- **不能与推荐算法的提升相加**：两者的反事实不同（“没被框架选中” vs “没有推荐算法”），相加会重复计算二者的交互部分。

### 3.2 计算方法

**第一步：每个“子人群 × 周期”做一次断点估计。** 运行变量是（选人分数 − 该子人群阈值），结果是用户在结果窗口内是否发生目标行为，**不论有没有被曝光**（意向处理效应 ITT）。

**第二步：合并估计，并分层。**

- 多个子人群、多个周期合并估计（带子人群固定效应）→ 得到更稳定的阈值处效应。
- 按“是否同时被人工覆盖”分层估计。人工覆盖在框架选人之前就确定了，所以分层后的估计仍然有效。预期被人工覆盖的用户增量更小。
- **利用阈值不同拼出“效应-分数曲线”**：不同子人群、不同周期的阈值落在不同的绝对分数上，每个阈值都给出一个“该分数水平上的边际效应”。把这些点连起来，可以看出高分用户的效应是更高还是更低。

**第三步：分“直接证据”和“外推”两部分汇总。**

```text
业务增量 = Σ 子人群 Σ 分层 [ 入选人数 × 对应效应 ]
         = 直接证据部分（阈值附近带宽内的入选用户 × 阈值处效应）     ← 【E1】
         + 外推部分（带宽外的入选用户 × 效应-分数曲线上的效应）     ← 【E1 + 外推假设】
```

外推规则：

- 只在**观测到的阈值分数范围内**沿曲线外推；超出范围的高分用户使用最近一段的效应，并单独列出人数。
- 区间同时反映统计误差（自助抽样）和外推的不确定性（曲线的置信带）。

### 3.3 示例（以下数字均为【虚构】）

交通，一个月度周期，6 个子人群，入选 420 万人（其中 240 万没有被人工覆盖，180 万同时被人工覆盖）。

| 部分 | 分层 | 入选人数 | 效应（95% 区间） | 增量（区间） |
|---|---|---|---|---|
| 直接证据 | 未被人工覆盖 | 35 万 | 1.6pp（0.6–2.6） | 0.56 万（0.21–0.91） |
| 直接证据 | 同时被人工覆盖 | 25 万 | 0.7pp（−0.2–1.6） | 0.18 万（−0.05–0.40） |
| 外推 | 未被人工覆盖 | 205 万 | 曲线 1.2–2.4pp | 2.5–4.9 万 |
| 外推 | 同时被人工覆盖 | 155 万 | 曲线 0.3–1.0pp | 0.5–1.6 万 |
| **合计** | | **420 万** | | **约 3.1–7.8 万** |

管理层版的写法：

> 9 月交通框架策略带来增量交易用户约 **3.1–7.8 万**【E1，含外推】。其中阈值附近有直接证据的部分为 0.2–1.3 万；其余部分依据“效应随分数变化”的规律外推。增量主要来自人工没有覆盖的用户；对人工已覆盖用户的额外增量较小，且尚不显著。

### 3.4 这个数字的有效性（直说）

- **大部分增量靠外推。** 在上面的虚构示例中，按区间中点算，直接证据只占约 1/7。管理层问的是“总增量”，而不加实验时最硬的证据只覆盖边际用户。这是本框架**最大的有效性缺口**（§6.2）。
- 外推的可信度取决于阈值的分散程度：阈值越分散（子人群多、周期多、阈值不同），曲线覆盖的分数范围越广，外推就越可靠。**每个月都要报告外推部分的占比**，作为这个数字的“可信度标签”。
- 区间较宽是真实不确定性的反映。为了显得精确而只报中间值，会在后续月份被打脸。

### 3.5 可选增强（需要决策，不是默认前提）

如果管理层需要一个**更硬的总增量数字**，有两个低成本的选项，都**不需要运营额外工作**：

| 选项 | 做法 | 能得到什么 | 代价【虚构量级】 |
|---|---|---|---|
| ① 入选用户小比例留出 | 每个子人群随机留出 5% 的入选用户，不下发框架任务（人工任务照常） | **全体入选用户的总增量**，直接估计，不需要外推 | 损失约 5% 的增量（虚构示例中约 0.2–0.4 万/月）；可检测差异约 0.24pp（`tools/power_calc.py holdout`） |
| ② 阈值附近随机入选 | 阈值上下一个很窄的分数带内，用随机数决定是否入选 | 阈值处效应从“准实验”变成“实验”，自检负担更小 | 几乎没有：带内用户分数本来就差不多 |

建议：如果“业务增量”是管理层评价策略中心的**主要依据**，推荐选项 ①。它的成本（约 5% 增量）远低于一个无法被质疑的数字的价值。是否采用由你和管理层决定（P10）；不采用时，框架照常运行，按 §3.3 的方式表达。

## 4. 七个分析模块

### 模块 A　覆盖分区与承接（事实底座）

- **问题**：框架任务覆盖了谁、曝光了谁、承接了多少；与人工重叠多少。
- **方法**：按周期初的人群包成员关系分四个区：Z1 仅框架（Z1a 真新覆盖 / Z1b 替代覆盖）、Z2 仅人工、Z3 共同覆盖、Z4 均未覆盖。用户层互斥；任务层承接同时报去重值。
- **等级**：【F】。**状态**：✅ 可以做（P5、P6、P7 影响细节）。

### 模块 B　找人增量：多阈值断点（增量主证据）

基本方法见 §3.2。以下是针对你的回答需要做的四项处理：

**① 任务下线（K6）**

- 下线不改变“谁被选中”，只降低入选用户实际得到的干预。所以 ITT 仍然有效，估的是“在真实运营决策下（包括下线）被选中的效果”。这正是管理层要的口径，**作为主口径**。
- 下线是在任务或子人群层面发生的，同一子人群内阈值两侧的比较不受影响。
- 诊断用：分别报告“有下线”和“未下线”子人群的效应。**注意**：只看未下线的子人群会挑出表现好的那些，高估平均效果，所以只作内部诊断。
- 需要：下线日志（时间、任务、原因）。【待补充：P2】

**② 策略调优（K7）**

| 调优内容 | 对 RDD 的影响 | 处理方式 |
|---|---|---|
| 只调货品、渠道 | 不影响“谁被选中” | ITT 照常；效果中包含调优的贡献 |
| 调人群或阈值 | 入选名单在周期内变化；如果用周期内的新行为重新打分，入选用户的新分数已经受到了干预的影响 | **以初始版本的“是否超过阈值”作为分组依据**（模糊断点：初始分组作为工具变量，“周期内是否曾被选中”作为实际处理）。**不能用调优后的分数做运行变量** |

- **调优功能本身的价值**：同一子人群调优前后的效应对比会混入时间因素，只能算【C】。如果要严格评估调优功能，需要一部分子人群不调优作为对照，这属于实验，默认不做。【待补充：P1、P2】

**③ 业务周期不同（K8）**

- 分析单位改为“**子人群 × 周期**”。每个周期单独估计，然后跨周期合并。
- 结果窗口**不超过周期长度**，避免下一个周期的入选结果污染对照组。周期较短（例如按周）时，单周期样本少，需要多周期合并（§6.5）。
- 检查“阈值下方用户在下个周期入选的比例”。比例高时，对照组在更长窗口内会被“处理”，长窗口结论要用模糊断点处理。
- 月报汇总**当月结束**的周期，并写明各业务的周期长度。

**④ 随机桶内的 RDD（诊断）**

- 在 5% 随机桶内单独做一次 RDD，得到“没有推荐算法放大时”的选人效应。和算法桶内的 RDD 对比，可以看出推荐算法对框架任务的放大或抑制作用。样本小，只作内部诊断，**不计入任何一方的价值**。

**等级**：阈值处【E1】；外推【E1 + 假设】；调优价值【C】。**状态**：✅ 可以做，P1、P2、P3 确认后定稿。

### 模块 C　组合质量：随机桶内比较

- **问题**：给同一类用户看框架任务还是人工任务，哪个转化更好？
- **方法**：随机桶内的 Z3 用户中，以“周期内第一次定向曝光是 F 任务还是人工任务”分组（等概率随机，K4），比较用户结果窗口内的转化。分别和 H1、H2 比较（随机桶内权重不生效，H2 可以直接比）。
- **定位**：**解释**模块 B 的增量从哪里来（组合好，还是找人准），**不与模块 B 相加**。
- **限制**：随机分发下的结论；无法测人群识别价值（K4）。
- **等级**：【E1】。**状态**：✅ 可以做。

### 模块 D　分发层隔离

- 算法桶 − 随机桶 → 推荐算法价值，归推荐团队。
- 某类任务在算法桶与随机桶中的曝光份额差 → 权重和算法对该类任务的影响，归分发层。
- 两个桶分发前月份的指标做 A/A 平衡检验。
- **等级**：【E1】。**状态**：✅ 可以做。

### 模块 E　效率

自动化任务占比、目标到上线周期、运营和 BI 人日、定向覆盖去重人数、供给盘活率、生产稳定性。人日可以货币化，但要注明“只有释放出来的人力被重新配置时才是真实节约”。详见详细方案 §8。**状态**：✅ 可以做（人日的精度取决于 P8）。

### 模块 F　预测确定性

- 按**周期**预测：承接预测 = Σ 子人群（入选人数 × 可投放率 × 曝光率 × 转化率），输出 P10/P50/P90。
- **增量预测**：入选人数 × 模块 B 的历史效应（含外推）。模块 B 连续 ≥ 3 个周期稳定后启用。这是管理层最关心的“可承诺增量”。
- 调优会改变周期内的策略：预测以**初始版本**为准，调优的影响在偏差拆解中单列一项。
- 偏差拆解：规模 → 可投放 → 曝光（归分发层）→ 转化 → 调优和下线。
- **状态**：✅ 可以做，需要 ≥ 3 个周期。

### 模块 G　质量围栏

补贴效率、打扰（频次、投诉）、承接用户后续留存、货品集中度、H3 曝光达成率、风控。只用来否决价值主张。**状态**：✅ 可以做。

## 5. 三类受众的输出

| 版本 | 读者 | 主要内容 | 证据等级 |
|---|---|---|---|
| **管理层版**（一页） | 管理层 | ① 业务增量区间，以及直接证据部分的占比（§3）② 人日节省 ③ 增量预测达成情况 ④ 固定边界声明 | F、E1 |
| **业务方承诺版** | 行业线负责人 | 下个周期的承接预测和增量预测（P25 作承诺值）；上个周期的偏差拆解；口径表 | F、E1 |
| **内部诊断版** | 策略中心团队 | 全部模块：分子人群和分周期的效应、效应-分数曲线、组合比较、下线和调优诊断、随机桶内 RDD、围栏、数据质量 | 全部，逐项标注 |

管理层版增量的固定写法：**“增量区间 + 直接证据部分 + 外推占比 + 一句话说明增量主要来自哪类用户”**，不给单点数字。

## 6. 框架有效性评估

### 6.1 逐模块评估

| 模块 | 构念效度 | 内部效度 | 外部效度 | 统计功效 | 主要风险 | 综合判断 |
|---|---|---|---|---|---|---|
| A 承接 | 中（衡量“参与”，不是“贡献”）| 不做因果 | 高 | 高 | 被当成贡献引用 | 事实底座，单独使用会误导 |
| B 阈值处效应 | **高** | **高**（K2、K6 让核心前提基本成立）| 只代表边际用户 | 中（取决于阈值附近样本）| 调人群型调优；周期重叠污染对照 | **增量主证据** |
| B 外推部分 | 高 | **中**：依赖“效应随分数平滑变化”的假设 | — | 低–中 | 阈值集中时曲线覆盖范围窄 | **管理层数字的主要不确定来源** |
| C 组合质量 | 高 | **高**（K4 等概率随机）| 中（随机分发 ≠ 算法分发）| 中（5% 桶）| 单周期“不显著”被误读为“没差别” | 有效，作为解释 |
| D 分发隔离 | 高 | 高 | — | 高 | 两个桶不平衡 | 有效 |
| E 效率 | 中 | 低（前后对比）| 高 | — | 人力未真正释放 | 有效，需注明口径 |
| F 预测 | 高 | 不做因果 | 中 | 需 ≥ 3 个周期 | 调优让初始预测失去意义 | 有效，起效慢 |
| G 围栏 | 中 | 低 | 高 | 中 | 阈值主观 | 作为否决机制有效 |

### 6.2 整体结论

1. **管理层的问题（总增量）和框架能提供的最硬证据（边际用户的增量）之间有缺口。** 框架用“效应-分数曲线”外推来填补，并且每期都报告外推占比。如果这个缺口不能接受，§3.5 的可选增强 ① 是最直接的补法。
2. **K2（未入选不会被其他子人群选中）和 K6（运营不能删人）让阈值处效应的内部效度很高**，这是框架最可靠的部分。
3. **策略调优是新出现的主要风险**：如果调优会改人群，并且用周期内的新数据重新打分，就必须坚持“以初始版本分组”，否则 RDD 会失效。P1、P2 的回答直接决定这一点。
4. **周期不同会降低单周期的统计功效**：短周期的业务需要多周期合并，结论滞后。
5. 框架仍然**不给**“占业务目标百分比”，也**不把**策略中心增量与推荐算法提升相加。

### 6.3 关键假设清单

| # | 假设 | 用在哪里 | 怎么检验 | 不成立时 |
|---|---|---|---|---|
| A1 | 分数在周期初算好，用户无法“挤过”阈值 | B | 阈值两侧密度检验；K6 已排除人工删人 | 降为 E2 |
| A2 | 阈值处没有其他干预同时跳变 | B | 阈值两侧的人工覆盖率、其他任务曝光、上周期行为是否连续 | 模糊断点 |
| A3 | 选中一个用户不影响其他用户（例如券预算有限） | B | 检查预算是否触顶 | 触顶周期标注“可能高估” |
| A4 | 效应随分数**平滑**变化 | B 外推 | 不同阈值处的效应点是否落在一条平滑曲线上；留一法交叉验证 | 外推部分降为 E2，管理层版只报直接证据部分和“外推参考” |
| A5 | 分组以初始版本为准时，调优不会反过来影响阈值下方用户 | B（调优） | 检查调优后阈值下方用户的入选率 | 模糊断点 |
| A6 | 结果窗口内，阈值下方用户没有被下个周期选中 | B（周期） | 统计下周期入选率 | 缩短窗口或用模糊断点 |
| A7 | 随机桶内等概率分发 | C | 实际曝光份额 vs 理论份额；两组分发前特征平衡 | 按概率加权 |
| A8 | hash 分流与用户行为无关 | C、D | A/A 检验 | DiD 校正 |
| A9 | 结果窗口足够长 | 全部 | 不同窗口的敏感性分析 | 选最保守的窗口 |
| A10 | 历史效应对下个周期有代表性 | F | 回测 | 放宽区间 |

### 6.4 框架自检（每个周期自动运行）

| 自检 | 通过标准 | 不通过时 |
|---|---|---|
| 安慰剂周期（RDD 套用到框架上线前） | 估计值的区间包含 0 | 模块 B 降级 |
| 安慰剂阈值（真实阈值两侧的假阈值） | 无显著跳变 | 检查 A2 |
| 密度检验 | 无显著跳变 | 检查 A1 |
| 协变量平衡（阈值两侧、随机桶内两组） | 标准化差异 < 0.1 | 降级或校正 |
| 曲线平滑性（A4） | 留一法预测误差在区间内 | 外推降为 E2 |
| 外推占比 | 报告即可 | 占比过高时在管理层版提示 |
| 随机桶 A/A | 无显著差异 | 校正 |
| 方法三角互证（RDD vs 匹配 DiD） | 方向一致，匹配结果不低于 RDD | 排查 |
| 预测回测 | 区间覆盖率 70%–90% | 调整区间 |

### 6.5 统计功效：工具与摸底清单

用 `tools/power_calc.py` 计算最小可检测差异（MDE）：

```bash
python tools/power_calc.py rdd     --p <基础转化率> --n1 <阈值上方带宽内人数> --n2 <阈值下方带宽内人数> --periods <合并周期数>
python tools/power_calc.py rct     --p <基础转化率> --n1 <随机桶F组人数> --n2 <随机桶H组人数> --periods <合并周期数>
python tools/power_calc.py holdout --p <基础转化率> --treated <正常投放入选人数> --holdout <留出人数>
```

虚构量级下的结果（仅演示）：随机桶组合比较单周期约 0.8pp、合并 3 个周期约 0.5pp；RDD 单周期约 0.6pp；5% 留出约 0.24pp。

**需要摸底的数字**（每个行业线、每个周期各取一份，近 3 个周期即可）：

| 数字 | 用途 |
|---|---|
| 各子人群的候选人数、入选人数、阈值 | B |
| 各子人群阈值上下 ±0.05 分（或 ±5% 分位）内的人数 | B 的功效 |
| 入选用户中同时被人工覆盖的比例 | B 的分层 |
| 不同子人群和周期的阈值分布（最小 / 最大 / 分位数） | 判断外推能覆盖多大范围 |
| 随机桶内 Z3 有定向曝光的人数 | C 的功效 |
| 候选用户在结果窗口内的基础转化率 | 全部 |
| 下线任务数和涉及人数；调优次数和涉及人数 | B 的处理强度 |

### 6.6 抗操纵性

| 可能的行为 | 会抬高的指标 | 防线 |
|---|---|---|
| 专挑“本来就会转化”的用户 | 承接 | 承接不作为 KPI；RDD 衡量增量，这种挑法不会抬高 RDD 结果 |
| 把阈值调得很低以扩大入选 | 增量总数（入选人数变多） | 效应-分数曲线会显示低分段边际效应下降；围栏 |
| 通过调优反复改人群 | 调优后的效果 | 坚持以初始版本分组 |
| 压低预测以保证“达成” | 承诺完成率 | 偏差方向指标；区间覆盖率过高也告警 |

**建议的 KPI 组合**：增量区间下界 + 外推占比 + 预测区间覆盖率 + 人日节省 + 围栏无告警。

### 6.7 已知盲区

1. 策略中心占业务目标的比例（分母无法拆解）。
2. 不采用 §3.5 时，远离阈值的高分用户的增量只能外推。
3. 调优功能本身的价值（只能到【C】）。
4. 框架任务在算法桶中与推荐算法的交互效应。
5. 跨周期的长期效应（例如用户习惯养成）。

## 7. 落地顺序

| 步骤 | 内容 | 依赖 |
|---|---|---|
| 1 | 回答 P1–P4；决定是否采用 §3.5（P10） | — |
