## 3. 管理层主指标：策略中心带来的业务增量

### 3.1 定义

> **业务增量** = 在其他一切照常的前提下（人工照常投放、推荐算法照常分发、供给不变），**框架策略选中这批用户**所带来的额外目标行为。

- 包含：框架选人、货品和渠道组合、周期内的调优和下线决策带来的综合效果。
- 不包含：推荐算法本身的价值、自然转化、新供给。
- 注意：被框架选中的用户里，有一部分也被人工覆盖了（Z3）。阈值下方的对照用户同样可能被人工覆盖，所以估出来的是**在人工已有投放之上**再多出来的部分，不会和人工重复认领。
- **不能与推荐算法的提升相加**：两者的反事实不同（“没被框架选中” vs “没有推荐算法”），相加会重复计算二者的交互部分。
- **随着人工投放减少，阈值下方的对照用户越来越接近“没有任何定向干预”**。这时估出来的增量就越来越接近“有策略中心 vs 没有策略中心”，正好是管理层想要的反事实。

**三个口径（K9）**：同一套方法、同一批候选用户，只换结果变量。

| 口径 | 结果变量（每个候选用户，未交易记 0） | 特点 | 处理 |
|---|---|---|---|
| 增量交易用户 | 结果窗口内是否交易（0/1） | 最稳定，区间最窄 | **管理层版的第一口径** |
| 增量交易笔数 | 结果窗口内交易笔数 | 包含“已经会交易的人交易得更多” | 极端值按 P99 截尾 |
| 增量交易金额 | 结果窗口内交易金额 | 波动最大，区间最宽；交通客单价低、缴费客单价差异大 | 按 P99 截尾；**同时列出补贴成本**，给出“金额增量 − 补贴”的参考值 |

三个口径的区间宽度不同，不要求同时显著。常见的情况是用户口径显著、金额口径不显著，月报中如实写出即可。功效计算：比例指标用 `--p`，笔数和金额用 `--sd`（§6.5）。

### 3.2 计算方法

**第一步：每个“子人群 × 周期”做一次断点估计。** 运行变量是（选人分数 − 该子人群阈值），结果是用户在结果窗口内是否发生目标行为，**不论有没有被曝光**（意向处理效应 ITT）。

**第二步：合并估计，并分层。**

- 多个子人群、多个周期合并估计（带子人群固定效应）→ 得到更稳定的阈值处效应。
- 按“是否同时被人工覆盖”分层估计。人工覆盖在框架选人之前就确定了，所以分层后的估计仍然有效。预期被人工覆盖的用户增量更小。
- **利用阈值不同拼出“效应-分数曲线”**：不同子人群、不同周期的阈值落在不同的绝对分数上，每个阈值都给出一个“该分数水平上的边际效应”。把这些点连起来，可以看出高分用户的效应是更高还是更低。
- **调优产生的新阈值也是曲线上的点（K7）**：扩大人群相当于在周期中途把阈值从 c₀ 降到 c₁，从调优生效那天起，c₁ 处就有一个新的断点（只用生效之后的结果）。交通每周产出、3–5 天调优一次，会积累大量这样的点。**注意**：只有表现好的子人群才会被扩大，所以这些点代表的是“表现好的子人群”，合并时要带子人群固定效应，不能直接代表全部。

**交通周度产出按月汇总**：月度增量 = 当月各周增量之和。为避免重复计算和遗漏，需要做两件事：

1. **按上周是否入选分层估计**：上周入选状态发生在本周分组之前，分层后的估计仍然有效。“上周未入选”层估的是新进入的效应；“上周已入选”层估的是继续入选的额外效应。两层分别乘人数再相加，就不会把上周的效应重复算进本周。
2. **跨周遗留效应不计入**：本周入选对下周交易的影响，在周度结果窗口内看不到，所以月度合计**偏保守**。可以用“上周入选对本周结果”的断点估计来检查遗留效应的大小，作为内部诊断。

**第三步：分“直接证据”和“外推”两部分汇总。**

```text
业务增量 = Σ 子人群 Σ 分层 [ 入选人数 × 对应效应 ]
         = 直接证据部分（阈值附近带宽内的入选用户 × 阈值处效应）     ← 【E1】
         + 外推部分（带宽外的入选用户 × 效应-分数曲线上的效应）     ← 【E1 + 外推假设】
```

外推规则：

- 只在**观测到的阈值分数范围内**沿曲线外推；超出范围的高分用户使用最近一段的效应，并单独列出人数。
- 区间同时反映统计误差（自助抽样）和外推的不确定性（曲线的置信带）。

### 3.3 示例（以下数字均为【虚构】）

交通，一个月度周期，6 个子人群，入选 420 万人（其中 240 万没有被人工覆盖，180 万同时被人工覆盖）。

| 部分 | 分层 | 入选人数 | 效应（95% 区间） | 增量（区间） |
|---|---|---|---|---|
| 直接证据 | 未被人工覆盖 | 35 万 | 1.6pp（0.6–2.6） | 0.56 万（0.21–0.91） |
| 直接证据 | 同时被人工覆盖 | 25 万 | 0.7pp（−0.2–1.6） | 0.18 万（−0.05–0.40） |
| 外推 | 未被人工覆盖 | 205 万 | 曲线 1.2–2.4pp | 2.5–4.9 万 |
| 外推 | 同时被人工覆盖 | 155 万 | 曲线 0.3–1.0pp | 0.5–1.6 万 |
| **合计** | | **420 万** | | **约 3.1–7.8 万** |

管理层版的写法：

> 9 月交通框架策略带来增量交易用户约 **3.1–7.8 万**【E1，含外推】。其中阈值附近有直接证据的部分为 0.2–1.3 万；其余部分依据“效应随分数变化”的规律外推。增量主要来自人工没有覆盖的用户；对人工已覆盖用户的额外增量较小，且尚不显著。

### 3.4 这个数字的有效性（直说）

- **大部分增量靠外推。** 在上面的虚构示例中，按区间中点算，直接证据只占约 1/7。管理层问的是“总增量”，而不加实验时最硬的证据只覆盖边际用户。这是本框架**最大的有效性缺口**（§6.2）。
- 外推的可信度取决于阈值的分散程度：阈值越分散（子人群多、周期多、阈值不同），曲线覆盖的分数范围越广，外推就越可靠。**每个月都要报告外推部分的占比**，作为这个数字的“可信度标签”。
- 区间较宽是真实不确定性的反映。为了显得精确而只报中间值，会在后续月份被打脸。

### 3.5 可选增强（需要决策，不是默认前提）

如果管理层需要一个**更硬的总增量数字**，可以考虑下列选项，都**不需要运营额外工作**。

**关于留出组浪费流量的问题。** 你的判断是对的：人工投放越来越少，被留出的用户在流量位上往往没有别的定向任务可看，这部分流量基本就浪费了。浪费的量恰好等于“留出比例 × 增量”。常设留出的成本会随着人工减少而变得越来越实在。因此不建议常设留出，改为下面的组合：

| 选项 | 做法 | 能得到什么 | 代价【虚构量级】 |
|---|---|---|---|
| ① **定期校准型留出**（推荐） | 不常设。交通每月只在 1 个周度周期里，每个子人群随机留出 5% 的入选用户；缴费每季度 1 个月度周期 | 用这一个周期的直接总增量，**校准** RDD 的外推曲线：外推结果落在留出估计的区间内，说明外推可信，其余周期继续用 RDD + 外推；不一致就修正曲线 | 交通约为月度增量的 1.25%（5% × 1/4 周）；缴费约为季度增量的 1.7%（5% × 1/3 月）。单个周期的可检测差异约 0.24pp（`tools/power_calc.py holdout`） |
| ② 阈值附近随机入选 | 阈值上下一个很窄的分数带内，用随机数决定是否入选 | 阈值处效应从“准实验”变成“实验” | **几乎没有浪费**：带内用户分数本来就和阈值下方差不多，不入选的人和平时没被选中的人一样 |
| ③ 扩大人群时随机分批 | 调优决定扩大人群时，新增的人随机分成两批，间隔 1–2 天生效 | 对扩大部分的效应做一次干净的估计，同时检验调优决策 | 很小：只是推迟一部分人 1–2 天 |
| ④ 留出用户改看“简单基线策略” | 留出用户不是什么都不看，而是看一个简单规则生成的任务（例如热门货品 + 默认渠道） | 估的是“框架策略 vs 简单策略”的增量，**流量不浪费** | 留出用户的体验略差；反事实变成“简单策略”，不是“没有策略中心”，汇报时要说清楚 |

建议：采用 ① + ②。① 每月或每季度校准一次外推，② 让阈值处效应更硬，两者合计的流量损失很小。如果管理层介意任何流量损失，用 ④ 替代 ①。是否采用由你和管理层决定（P4）；都不采用时，框架照常运行，按 §3.3 的方式表达。

## 4. 七个分析模块

### 模块 A　覆盖分区与承接（事实底座）

- **问题**：框架任务覆盖了谁、曝光了谁、承接了多少；与人工重叠多少。
- **方法**：按周期初的人群包成员关系分四个区：Z1 仅框架（Z1a 真新覆盖 / Z1b 替代覆盖）、Z2 仅人工、Z3 共同覆盖、Z4 均未覆盖。用户层互斥；任务层承接同时报去重值。
- **等级**：【F】。**状态**：✅ 可以做（P5、P6、P7 影响细节）。

### 模块 B　找人增量：多阈值断点（增量主证据）

基本方法见 §3.2。以下是针对实际运营方式需要做的五项处理：

**① 任务下线（K6）**

- 下线不改变“谁被选中”，只降低入选用户实际得到的干预。所以 ITT 仍然有效，估的是“在真实运营决策下（包括下线）被选中的效果”。这正是管理层要的口径，**作为主口径**。
- 下线发生在任务或子人群层面，同一子人群内阈值两侧的比较不受影响。
- 诊断用：分别报告“有下线”和“未下线”子人群的效应。**注意**：只看未下线的子人群，会挑出表现好的那些，高估平均效果，所以只作内部诊断。
- 下线日志已具备（K11）。

**② 按效果扩大或缩小人群（K7）**

调优是“看效果再调整”的自适应过程：初始阈值 c₀ → 效果好时降到 c₁ 扩大人群 → 效果不好时升到 c₂ 缩小人群 → 仍然不好就下线。处理原则：

| 问题 | 处理 |
|---|---|
| 主口径怎么分组 | **一律以初始阈值 c₀ 分组**，结果窗口覆盖整个周期。估的是“在初始版本被选中，并经历后续全部调优和下线”的效果，也就是策略中心这套自适应流程的真实效果【E1】 |
| 扩大后，c₀ 下方有人被选中了 | c₀ 处变成“模糊断点”：用“初始是否超过 c₀”作为工具变量，“周期内入选天数”作为实际处理，可以换算出“每入选一天”的效应 |
| 扩大产生的新阈值 c₁ | 从扩大生效那天起，c₁ 处是一个新的断点（只用生效之后的结果）。给效应曲线补上**低分段**的点，也能直接回答“这次扩大值不值” |
| 缩小产生的新阈值 c₂ | c₂ 两侧的人在缩小之前都被选中过，比较的是“继续入选 vs 停止入选”的效应，**和主口径不是一回事**，只作诊断 |
| 不能做的事 | **不能用调优时重新计算的分数做运行变量**，因为入选用户的新分数可能已经受到前几天干预的影响（P2） |

**③ 交通周度产出（K8）**

- 每周一个分析单位；结果窗口 = 7 天，不跨周。
- 周内 3–5 天发生调优：主口径照 ② 以周初阈值分组，结果窗口覆盖整周。
- 按上周是否入选分层估计，再按月汇总（方法见 §3.2）。
- 每周检查“上周入选状态在本周阈值处是否连续”。如果分数很稳定，阈值上方的人上周也更可能被选中，需要靠分层来隔开。
- 缴费按月产出，单周期样本较多，跨周期问题较小。

**④ 随机桶内的 RDD（诊断）**

- 在 5% 随机桶内单独做一次 RDD，得到“没有推荐算法放大时”的选人效应。和算法桶内的 RDD 对比，可以看出推荐算法对框架任务是放大还是抑制。样本小，只作内部诊断，**不计入任何一方的价值**。

**⑤ 调优决策质量（新增诊断）**

调优本身是策略中心的能力，需要单独评估：

| 指标 | 定义 | 等级 |
|---|---|---|
| 扩大决策的边际增量 | 扩大生效后，c₁ 处的断点效应：> 0 说明扩大是值得的 | 【E1】 |
| 缩小决策的边际增量 | c₂ 处“继续入选 vs 停止入选”的效应：≈ 0 或 < 0 说明缩小是对的 | 【E1】（诊断） |
| 下线决策的正确率 | 被下线子人群在下线前的阈值处效应，是否确实低于未下线子人群 | 【E2】 |
| 调优信号与真实增量的一致性 | 调优时用的“效果好坏”信号，和事后估出的增量是否同方向 | 【F】（对比结果） |

**关于调优信号的提醒（P1）**：如果“效果好”是用**入选人群的转化率**判断的，调优会倾向于扩大“本来就会转化”的人群，而不一定是“有增量”的人群。阈值两侧的转化率差可以在周期内实时计算，建议把它作为调优信号（或者至少作为一个参考信号）。3–5 天的数据噪声较大，可以向该子人群的历史效应收缩后再用。

**等级**：阈值处【E1】；外推【E1 + 假设】；扩大决策【E1】；调优功能整体价值【C】。**状态**：✅ 可以做，P1、P2、P3 确认后定稿。

### 模块 C　组合质量：随机桶内比较

- **问题**：给同一类用户看框架任务还是人工任务，哪个转化更好？
- **方法**：随机桶内的 Z3 用户中，以“周期内第一次定向曝光是 F 任务还是人工任务”分组（等概率随机，K4），比较用户结果窗口内的转化。分别和 H1、H2 比较（随机桶内权重不生效，H2 可以直接比）。
- **定位**：**解释**模块 B 的增量从哪里来（组合好，还是找人准），**不与模块 B 相加**。
- **限制**：随机分发下的结论；无法测人群识别价值（K4）。
- **等级**：【E1】。**状态**：✅ 可以做。

### 模块 D　分发层隔离

- 算法桶 − 随机桶 → 推荐算法价值，归推荐团队。
- 某类任务在算法桶与随机桶中的曝光份额差 → 权重和算法对该类任务的影响，归分发层。
- 两个桶分发前月份的指标做 A/A 平衡检验。
- **等级**：【E1】。**状态**：✅ 可以做。

### 模块 E　效率

自动化任务占比、目标到上线周期、运营和 BI 人日、定向覆盖去重人数、供给盘活率、生产稳定性。人日可以货币化，但要注明“只有释放出来的人力被重新配置时才是真实节约”。详见详细方案 §8。**状态**：✅ 可以做（人日的精度取决于 P8）。

### 模块 F　预测确定性

- 按**周期**预测：承接预测 = Σ 子人群（入选人数 × 可投放率 × 曝光率 × 转化率），输出 P10/P50/P90。
- **增量预测**：入选人数 × 模块 B 的历史效应（含外推）。模块 B 连续 ≥ 3 个周期稳定后启用。这是管理层最关心的“可承诺增量”。
- 调优会改变周期内的策略：预测以**初始版本**为准，调优的影响在偏差拆解中单列一项。
- 偏差拆解：规模 → 可投放 → 曝光（归分发层）→ 转化 → 调优和下线。
- **状态**：✅ 可以做，需要 ≥ 3 个周期。

### 模块 G　质量围栏

补贴效率、打扰（频次、投诉）、承接用户后续留存、货品集中度、H3 曝光达成率、风控。只用来否决价值主张。**状态**：✅ 可以做。

## 6. 框架有效性评估

### 6.1 逐模块评估

| 模块 | 构念效度 | 内部效度 | 外部效度 | 统计功效 | 主要风险 | 综合判断 |
|---|---|---|---|---|---|---|

| B 阈值处效应 | **高** | **高**（K2、K6 让核心前提基本成立）| 只代表边际用户 | 中（取决于阈值附近样本；交通单周样本少）| 自适应调优让 c₀ 处变成模糊断点；周度跨周影响 | **增量主证据** |

| F 预测 | 高 | 不做因果 | 中 | 需 ≥ 3 个周期 | 调优让初始预测失去意义 | 有效，起效慢 |
| G 围栏 | 中 | 低 | 高 | 中 | 阈值主观 | 作为否决机制有效 |

### 6.2 整体结论

1. **管理层的问题（总增量）和框架能提供的最硬证据（边际用户的增量）之间有缺口。** 框架用“效应-分数曲线”外推来填补，并且每期都报告外推占比。如果这个缺口不能接受，§3.5 的可选增强 ① 是最直接的补法。
2. **K2（未入选不会被其他子人群选中）和 K6（运营不能删人）让阈值处效应的内部效度很高**，这是框架最可靠的部分。
3. **自适应调优既是风险也是机会。** 风险：调优会改人群，所以必须坚持“以初始阈值分组”，否则 RDD 会失效。机会：每次扩大人群都会产生一个新的断点，给效应曲线补上低分段的点，还能直接检验“这次扩大值不值”。
4. **交通周度产出会降低单周的统计功效，并带来跨周影响。** 需要按上周入选状态分层、多周合并。月度合计不包含跨周遗留效应，所以偏保守。
5. **三个口径的可信度不同**：交易用户最稳定；交易笔数次之；金额波动最大，可能长期不显著。管理层版以交易用户为第一口径。
6. **调优信号是一个潜在的系统性偏差**：如果调优按入选人群的转化率判断效果，就会把策略往“本来就会转化”的人群方向推，增量反而可能下降。§4 模块 B ⑤ 的“调优信号与真实增量的一致性”专门监控这一点。
5. 框架仍然**不给**“占业务目标百分比”，也**不把**策略中心增量与推荐算法提升相加。

### 6.5 统计功效：工具与摸底清单

用 `tools/power_calc.py` 计算最小可检测差异（MDE）：

```bash
python tools/power_calc.py rdd     --p <基础转化率> --n1 <阈值上方带宽内人数> --n2 <阈值下方带宽内人数> --periods <合并周期数>
python tools/power_calc.py rct     --p <基础转化率> --n1 <随机桶F组人数> --n2 <随机桶H组人数> --periods <合并周期数>
python tools/power_calc.py holdout --p <基础转化率> --treated <正常投放入选人数> --holdout <留出人数>
# 交易笔数、金额口径：把 --p 换成 --sd <人均笔数或人均金额的标准差（含 0，金额先按 P99 截尾）>
python tools/power_calc.py rdd     --sd <标准差> --n1 <...> --n2 <...>
```

虚构量级下的结果（仅演示）：随机桶组合比较单周期约 0.8pp、合并 3 个周期约 0.5pp；RDD 单周期约 0.6pp；5% 留出约 0.24pp。

**需要摸底的数字**（每个行业线、每个周期各取一份，近 3 个周期即可）：

| 数字 | 用途 |
|---|---|
| 各子人群的候选人数、入选人数、阈值 | B |
| 各子人群阈值上下 ±0.05 分（或 ±5% 分位）内的人数 | B 的功效 |
| 入选用户中同时被人工覆盖的比例 | B 的分层 |
| 不同子人群和周期的阈值分布（最小 / 最大 / 分位数） | 判断外推能覆盖多大范围 |
| 随机桶内 Z3 有定向曝光的人数 | C 的功效 |
| 候选用户在结果窗口内的基础转化率 | 全部 |
| 下线任务数和涉及人数；调优次数和涉及人数 | B 的处理强度 |
| 扩大和缩小的次数，以及每次新阈值附近的人数 | 调优产生的新断点能否单独估计 |
| 交通：用户连续多周入选的比例；上周入选用户在本周候选中的占比 | 跨周影响的大小 |
| 候选用户结果窗口内人均交易笔数、人均金额（P99 截尾）的均值和标准差 | 笔数、金额口径的功效 |

### 6.6 抗操纵性

| 可能的行为 | 会抬高的指标 | 防线 |
|---|---|---|
| 专挑“本来就会转化”的用户 | 承接 | 承接不作为 KPI；RDD 衡量增量，这种挑法不会抬高 RDD 结果 |
| 把阈值调得很低以扩大入选 | 增量总数（入选人数变多） | 效应-分数曲线会显示低分段边际效应下降；围栏 |
| 通过调优反复改人群 | 调优后的效果 | 坚持以初始阈值分组 |
| 用入选人群转化率作为调优信号 | 承接、入选人群转化率 | 监控“调优信号与真实增量的一致性”（模块 B ⑤）；建议改用阈值两侧差作为信号 |
| 压低预测以保证“达成” | 承诺完成率 | 偏差方向指标；区间覆盖率过高也告警 |

**建议的 KPI 组合**：增量区间下界 + 外推占比 + 预测区间覆盖率 + 人日节省 + 围栏无告警。

### 6.7 已知盲区

1. 策略中心占业务目标的比例（分母无法拆解）。
2. 不采用 §3.5 时，远离阈值的高分用户的增量只能外推。
3. 调优功能的整体价值（“有调优 vs 没有调优”只能到【C】）。单次扩大决策值不值可以到【E1】（模块 B ⑤）。
4. 框架任务在算法桶中与推荐算法的交互效应。
5. 跨周期的长期效应（例如用户习惯养成）。
